# 03_RESUME — 引き継ぎ再開フロー(AIの手順)

ユーザーが「AI_KEY の 10_PROJECTS から選ばせて」等と言ったときのAIの動作。
このフロー自体は機密操作を含まないので、TIER判定とは独立に実行してよい。

## A. 既存PJの再開(走者交代)
1. `10_PROJECTS/*.md` を列挙し、各ファイルから 名前 / 状態 / repo所在 / 起動プロンプト を読む。
2. ユーザーへ**選択肢として提示**する(1件でも勝手に決めず提示)。
3. 選ばれたPJの repo へ移動し、そのファイルの「起動プロンプト」に従う
   (通常: `AGENTS.md` → `docs/STATE.md` の残作業から着手)。
4. repo が見つからない(未clone等)なら、所在を提示してユーザーに確認する。

## B. 新規PJへの導入
- 対象は**現在の作業repo**(選択でなく確認)。dev-conventions のテンプレから
  `AGENTS.md` / `docs/STATE.md` / `docs/LOG.md` を作る。
- 済んだら `10_PROJECTS/` に所在ポインタを1枚追加
  (雛形: sleep_v3.md。書くのは「所在・残作業・儀式」の3点だけ)。

## 禁止
- このフローを口実に、ユーザー未確認で 破壊的操作 / 外部送信 / 課金 をしない(02_RULES 恒久禁止)。
- PJ状態を変えたら終了時に該当 `10_PROJECTS/*.md` を更新する(00_BOOT 終了時の義務)。
