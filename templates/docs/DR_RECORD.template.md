# DR審査記録 / Design Review Record（任意テンプレート）

> 採用する場合はプロジェクトのレビュー記録としてコピーする。全プロジェクトに新規ファイルを強制しない。原則: dev-conventions `docs/DEVELOPMENT_PHILOSOPHY.md` §16。
> 記録があることとDRが承認されたことは異なる。

## 識別
- 製品 / リポジトリ:
- 変更対象 / 版 / ブランチ / 基準コミット:
- 審査ステージ: DR0 / DR1 / DR2 / DR3 / DR4 / DR5 / 初回出荷審査 / DR6（統合審査なら `DR123` 等の内訳を記入）
- 審査区分: 正式DR / 統合DR / 軽量DR / 緊急変更の事後審査
- 審査日 / 実施者 / 決定権者（明示委任の根拠）:

## 審査目的と対象
- 顧客・ユーザー価値と要求:
- 既存仕様、重複、止める・統合する作業:
- 対象と非対象 / 受入基準:
- 影響評価（安全・セキュリティ・品質・データ・法令・顧客・運用）:

## 市場性・事業性（DR1のみ。詳細は専用ゲート）

- **DR1の場合:** 専用記録テンプレート [DR1_INVESTMENT_GATE_RECORD.template.md](DR1_INVESTMENT_GATE_RECORD.template.md) と docs/DR1_INVESTMENT_GATE_V1.md を使用する。
- DR1の6軸・N/A・3者採点・PENDINGの扱いは専用ゲートに従う。
- DR2〜DR6の通常審査に、DR1の市場採点表や自社製品の販売/CAC/継続率等を遡及適用しない。
- DR1以外で大きな投資判断が必要な場合は、その段階の目的に合った独立の投資メモを作る。

## 段階別判断（統合DRでも省略しない）
| DR段階 | 対応する問い | 成果物・証拠とリンク | 未検証点 | 段階判定 |
| --- | --- | --- | --- | --- |
| （例: DR1） | （市場・要求、差別化・数値的事業性は明確か） | （市場/競合/需要/収益モデル等） | NOT_RUN / UNVERIFIED等 | GO / CONDITIONAL GO / REWORK / PENDING / STOP |

## 複数AIによる独立評価・相互批判（重要DRで使用）

- 共通証拠パッケージ（版・リンク・取得日）:
- 評価依頼・判定基準:
- GPT等の初回独立評価（相手の結論を開示する前）: 判定 / 根拠 / 確信度 / リスク / 未確認事項
- Claude等の初回独立評価（相手の結論を開示する前）: 判定 / 根拠 / 確信度 / リスク / 未確認事項
- 独立評価の実施状態: DONE / NOT_RUN（独立性が損なわれた場合は理由）
- 相互批判: 指摘 / 根拠 / 対象AIの応答（受け入れる・一部受け入れる・反論・判断不能）
- 各AIの再評価と結論変更理由:
- 未解消の反対意見・少数意見:
- ユーザーの見解に対する検証・AIの異論:
- ユーザーの最終判断・理由・承認日時:
- 受け入れた残存リスク・条件:
- 多数決で決めていないことの確認:

## 検証とリスク
- Verification（要求・設計との適合）:
- Validation（実際の目的・使い方で妥当か）:
- 修正前FAIL / 自動テスト / 回帰 / 必要な実機評価:
- 独立レビュー担当と証拠（自己検証と区別）:
- 未解決課題: 影響 / オーナー / 期限 / 確認条件 / 停止条件
- ロールバック・次段階での観測:

## 決定（人間/明示委任者のみ確定）
- 判定: 未決定 / GO / CONDITIONAL GO / REWORK / PENDING / STOP
- 判定根拠・承認者・日時・承認経路:
- 条件付きの場合の残課題・期限・閉鎖方法:
- 次に進める工程と範囲 / 進めない工程:
- 再DRの条件・差戻し先:
- `docs/LOG.md` の決定履歴、`docs/STATE.md` の現在地へのリンク:

> DR5の準備完了は初回出荷審査の承認ではない。DR6は出荷後に反復する。通常の更新は変更リスクに応じた適切なリリース判断を適用する。
